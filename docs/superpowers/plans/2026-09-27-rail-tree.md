# The rail as a tree — implementation plan

> **For agentic workers:** one task at a time, each with its own gate. Steps use `- [ ]`.

**Goal:** the assistant block's rail reads as a tree: a flat top group, a `Projects` section of collapsible folders holding conversations, and a `Recents` section with the active row highlighted.

**Architecture:** composition only. The block's existing rail state gains a group per conversation; folders are the kit's `collapsible` around the rows the rail already renders; search and folder-open state are one mechanism.

**Spec:** `docs/superpowers/specs/2026-09-27-rail-tree-design.md` — read it first; it is short and every decision is there.

## Global Constraints

- **Composition, no new kit component** (spec 8.1). If a task finds itself adding public API, stop and report.
- **Not the file tree** (spec 8.2). `kai-file-tree` is path-based with file-shaped rows.
- **One ordering, derived** (spec 8.3): sections come from the rows; never a second parallel list.
- Behaviors prop-driven; never CSS-manipulate, never pierce a shadow root. Derive it, don't type it. Decide loudly.
- **A block change reaches the page through `gen-blocks` then `copy-blocks`**, or a `dev:blocks` restart.
- Never wrap a command in a heredoc, and never pipe a long-running command into `tail`; **if a command hangs, run `ps` first**.
- A comment naming a kai element in angle brackets can trip the react-tree gate (`/<kai-[\w-]+/` over emitted `.tsx` does not distinguish a comment from a tag) — describe the element in words.
- Stage only the files you touch; check `git diff --cached --name-only`.

### Task 1: The state — a conversation belongs to a group

**Files:** `packages/blocks/blocks/assistant/assistant.controller.ts` (the conversation summaries), `states.mjs`.

- [ ] Give each conversation summary a group, and **derive the rail's sections from the rows** rather than keeping a second list. `New chat` and the top group stay as they are.
- [ ] Keep the existing ordering rules: **pinned first within its own folder**, `Recents` purely by recency (spec 8.4).
- [ ] Driver states: a folder collapsed and expanded; a folder with one conversation; the active row inside an open folder.
- [ ] Gate: `verify:blocks` and the driver's record + check. Commit.

---

### Task 2: The composition — folders around the existing rows

**Files:** the block's rail markup and CSS.

- [ ] Render each group as a **disclosure control from the kit's `collapsible`**, with the conversation rows the rail already renders as its children, indented one step. The rows keep their own keyboard contract and their row menu (rename, delete, pin) unchanged.
- [ ] **The open state lives in the block's state**, not in the DOM, so `Show more` and search can drive it.
- [ ] **`Show more`**: a muted row when a folder holds more rows than the rail shows, revealing the rest. It sits **outside** the row keyboard contract (spec 4).
- [ ] **Search spans every folder and opens the one it matched in** (spec 8.5) — one mechanism with the open state, not two.
- [ ] **Measure the indentation in a browser** — the hierarchy is the feature, and jsdom measures nothing. Extend a probe or write one beside the others.
- [ ] Gate: `verify:blocks` (both renderers), the driver, and the probe. Commit.

---

### Task 3: The states and the review artifacts

**Files:** `states.mjs`, `baselines/assistant.json`, `baselines/screenshots-assistant/`.

- [ ] Cover the two cases that always break when spacing is only approximately right: **one conversation**, and **many**.
- [ ] Re-record the screenshots the rail appears in. **Revert any shot that differs only by run noise** (a caret, a timestamp, ~100 bytes) — commit the ones whose size actually moved.
- [ ] Gate: `verify:blocks`, the full unit suite with its file count. Commit.
