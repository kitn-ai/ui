<Aside type="tip" title="When to use">
Reach for `Image` when you have a *reference*: a photo in your library, a chart your API rendered, an avatar the app uploaded. For image *data* a model or a tool handed you (bare base64 or a `Uint8Array`), use [Image artifact](/components/image-artifact/) instead: it owns the media type and the object-URL lifecycle, and this one would make you build both.
</Aside>

## Usage

Set `src` to the image address and `alt` to a real description. Every form of image URL works: https, a `data:` URI, and a `blob:` object URL the app created itself.

```html
<kai-image src="https://example.com/photo.jpg" alt="A mountain landscape at dusk"></kai-image>

<!-- an inline SVG, no request at all -->
<kai-image src="data:image/svg+xml;base64,PHN2ZyB4bWxucz0i…" alt="A purple star icon"></kai-image>
```

`alt` is required rather than optional, because an image with no name is invisible to a screen reader and a placeholder string ("image") is worse than none.

The element does not filter schemes: an `<img>` cannot execute one, so a `data:image/*`, an https URL and a blob all render. Where a URL is *navigable* the kit applies its own policy; that is a different guard for a different sink.
